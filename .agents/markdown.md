# Markdown 유지관리

## 도구와 범위

- Markdown 파일은 `.md` 확장자로 통일한다.
- `.prettierrc.json`의 Markdown 설정으로 문서를 포맷한다.
  공백·들여쓰기는 Prettier만 담당한다.
- 문장은 한 문장당 한 줄로 직접 작성한다.
  문단 사이의 빈 줄은 유지하고, 목록의 다음 문장은 같은 항목의 들여쓰기를 유지한다.
  `proseWrap: preserve`로 작성한 줄바꿈을 보존하며 글자 수에 따라 문장을 자동으로 나누지 않는다.
- `.markdownlint-cli2.jsonc`는 제목 구조·코드 언어·빈 링크·이미지 대체 텍스트·링크 참조를 검사한다.
  포맷 규칙을 중복으로 켜지 않는다.
- 일반 문서와 `.agents/`, `_posts/`의 Markdown을 모두 처리한다.
  의존성·생성 파일과 내부 `.gitignore`로 제외한 작업 폴더는 검사하지 않는다.

## 내용 보존

- 코드 예제, 수식, 의미 있는 줄바꿈과 Jekyll front matter를 보존한다.
  다른 언어의 예제를 Markdown 포맷 단계에서 다시 포맷하지 않는다.
- Liquid `highlight`는 Markdown 문법이 아니다.
  기존 두 블록의 Prettier 범위 제외와 markdownlint 비활성화 주석은 코드 본문을 그대로 보존하기 위한 것이므로 유지한다.
  제외 범위를 문서 전체로 넓히지 않는다.
- 게시물 제목은 front matter와 Jekyll 레이아웃에서 제공한다.
  같은 제목을 본문 H1으로 중복 추가하지 않는다.
- README에는 사용자에게 필요한 내용만 둔다.
  작업 계획·검증 기록은 `.local-quality/`, 유지관리 지침은 `.agents/`에 기록한다.

## 검증

- `npm run fix:md`는 두 도구의 가능한 수정을 모두 실행하고, 어느 한쪽에 오류가 남으면 실패한다.
- `npm run check:md`로 재검사하고 두 번째 수정 실행에 변경이 없는지 확인한다.
- Jekyll 빌드 전후의 문구·링크·코드·화면이 유지되는지 확인한다.
  기존 HTML·JS·CSS·UTF-8 검사도 유지한다.
- 승인 전에는 파일 수정과 로컬 검증까지만 진행한다.
  CI 연결 후에는 실제 자동 수정·커밋과 남은 오류의 배포 차단을 검증하고 테스트 이력을 제거한다.
