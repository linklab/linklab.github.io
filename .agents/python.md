# Python 유지관리

- 자체 Python 스크립트와 강의 예제 전체에 `ruff.toml`의 Ruff 기준을 적용한다.
  의존성·생성 결과·작업 폴더는 제외하며 새 Python 파일에도 같은 기준을 적용한다.
- `.github/requirements-lint.txt`로 도구를 설치한다.
  `npm run fix:py`는 안전한 린트 수정 후 포맷팅하고, `npm run check:py`는 린트와 포맷을 검사한다.
  자동 수정 명령에 unsafe 수정은 포함하지 않는다.
- 공백·줄바꿈·따옴표는 포맷터가 담당한다.
  린터는 미정의 이름·미사용 코드·import 순서, 타입 주석, 내장 이름 충돌과 오류 가능성이 있는 패턴을 검사한다.
  preview와 포맷터의 따옴표·공백 규칙은 중복 적용하지 않는다.
- 강의 예제의 주소·포트·송수신 방식, 스크립트의 파일 경로·출력·외부 서비스 요청 동작을 보존한다.
  검증 중 실제 앨범 다운로드나 외부 서비스 호출을 실행하지 않는다.
- 남은 오류가 있어도 다른 파일의 안전한 수정과 포맷팅은 실행해야 한다.
  수정·재검사·재실행 무변경·로컬 자동 커밋을 확인하고, 승인 후 CI에서 실제 자동 커밋과 잔여 오류의 경고와 배포 계속을 검증한다.
- Python 설정 파일은 Jekyll 배포 대상에서 제외한다.
  사용자용 README에 도구 유지관리 설명을 추가하지 않는다.
- CI는 기존 Python 도구 설치 단계에서 고정 버전 Ruff를 설치한다.
  자동 커밋 전에 `fix:py`, 커밋 후에 `check:py`를 실행하며 남은 오류는 경고로 남기고 빌드·배포를 계속한다.
